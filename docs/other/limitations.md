# 已知限制

这些是当前版本（3.0.7）确实做不到的事，写在这里避免误以为是 bug。

## 结构还原

### 方块实体内容不恢复

还原结构时只写回方块的**类型与状态**，不写回方块实体数据：

- 箱子 / 木桶 / 潜影盒：**里面的物品会丢**
- 告示牌：文字丢失
- 熔炉、酿造台、唱片机等：内部状态丢失

### 含水方块会变干

结构文件里水在第二层（liquid layer），当前只写回主层，所以含水的台阶、栅栏等还原后是干的。

### 单次操作有上限

| 操作 | 配置键 | 默认上限 |
|---|---|---|
| 形状生成 | `maxPlaceBlocks` | 40000 块 |
| 撤销 / 重做 / 粘贴 / 载入 | `maxRestoreBlocks` | 2000000 块 |

超过上限会被明确拒绝（不会破坏已经存在的撤销快照）。确实需要更大时可以调高，但耗时与内存会同步上升。

## 区块加载

- 依赖 `/tickingarea` 常加载区块，BDS 全局上限是 **10 个**；CALL 同一时刻最多占用 1 个，用完立即释放。
- `chunkLoader` 设成 `none` 时，超出玩家已加载范围的选区会失败。
- 距离玩家很远的区域首次操作需要**生成**区块，可能耗时数秒到数十秒。

## 选区显示

- 默认的 `structure_block` 模式会在选区上方放一个**临时结构方块**（只放在空气块上，正常退出会还原）。若服务器在操作期间崩溃，下次启动会自动还原。
- `particle` 粒子模式**尚未确认**在实机上能正常渲染。

## 客户端相关

- **boss 条已全面移除**：旧版用 boss 条显示进度时，颜色值越界会导致客户端掉线。现在进度一律是文字提示。
- 客户端掉线与服务端崩溃是两回事：服务端日志里没有 `logs/crash/` 新 dump 时，通常说明是客户端侧断开。
