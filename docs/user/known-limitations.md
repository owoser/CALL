# 已知限制

本页只列**引擎层面做不到**、或明确决定不做的能力，避免反复试探。

## 画（painting）与展示框：不在支持范围

**结论：复制、预览、粘贴都不处理画与展示框。** 这是"没有安全的落地方式"，不是"忘了做"。

实测记录（LL 26.51 / LSE 0.22）：

| 尝试的通路 | 结果 |
|---|---|
| 读取捕获的结构 NBT | 字节里**能看到** actor 标识（例如 `armor_stand`），但通过 LSE 的 NBT API **读不出条目**（`structure.entities` 取不到内容），脚本层没有可靠的读取入口 |
| `/summon minecraft:painting` | 失败；同样命令召唤盔甲架成功 |
| `mc.spawnMob("minecraft:painting")` | 返回 `null`；盔甲架成功 |
| 库的协议实体（`entityCreateAdvanced`） | 能生成，但缺少画的图案/尺寸数据，**真实客户端渲染时崩溃**（服务端完全无感） |
| `/structure save … true` + `/structure load … none true` | 唯一能携带实体的通道（实测方块+实体一起往返、支持旋转参数），但只能加载**引擎自己存过的结构**，且仅当前会话有效 |

因此：

- 复制一个含画的选区 → 方块正常，**画被忽略**（不报错，也不提示"丢失了画"）；
- 粘贴 → 目标位置不会出现画；
- 预览 → 不显示画；
- 需要保留画时，请手动补放。

> 若将来要做，唯一可行路线是把"含实体的粘贴"整体切到引擎的 `/structure save|load` 通道，并先完成"同一结构两条路径各贴一次、逐格比对"的对照验证，同时接受"仅当前会话有效"。

## 实体（生物、掉落物）

- 复制只记录**方块**与方块实体（箱子、告示牌、旗帜等），不记录生物、掉落物、经验球。
- 粘贴同理：不会生成任何实体。

## 结构内容

### 方块实体内容不保存

复制 / 预览只记录方块的**类型、状态与外观**，不保存方块实体数据：

- 箱子 / 木桶 / 潜影盒：**内容不会被复制**（预览里能看到内容，是实时读的世界数据）；
- 告示牌：文字不会被复制；
- 熔炉、酿造台、唱片机等：内部状态不会复制。

粘贴或撤销覆盖一个**仍装着东西**的容器时，插件会先用容器 API 把它清空
（`silentContainerClear`，默认开），所以物品**不会掉一地**——但也不会被搬走。

### 含水方块会变干

结构文件里水在第二层（liquid layer），当前只写回主层，含水的台阶、栅栏等还原后是干的。

## 规模上限

| 操作 | 配置键 | 默认上限 |
|---|---|---|
| 粘贴 / 形状放置 | `maxPlaceBlocks` | 40000 块 |
| 撤销 / 重做 / 载入 | `maxRestoreBlocks` | 2000000 块 |
| 预览显示 | `previewMaxBlocks` | 12000 块（超出转分片窗口） |

超过上限会被明确拒绝，不会破坏已有的撤销快照。

## 区块加载

- 依赖 `/tickingarea` 常加载区块，BDS 全局上限 **10 个**；CALL 同一时刻最多占 1 个，用完立即释放。
- `chunkLoader` 设为 `none` 时，超出玩家已加载范围的选区会失败。
- 很远的区域首次操作需要**生成**区块，可能耗时数秒到数十秒。

## 选区显示

- `wireframe` 用库的线框绘制，不占方块、不写世界；`none` 关闭。
- 选区信息是聊天栏/动作栏文字，不再使用 boss 条。

## 客户端相关

- 客户端掉线与服务端崩溃是两回事：服务端日志里没有新 crash dump 时，通常是客户端侧断开。
- 预览超过 `viewMaxDistance` 的部分不会下发，走到近处才会补上。
