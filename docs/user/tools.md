# 工具物品

3.2.0 起，CALL 自带一套工具物品，**不用记指令**也能完成"选区 → 复制 → 预览 → 粘贴"。

!> 这些物品是插件自带 addon（行为包 + 资源包）定义的自定义物品，id 是 `call:xxx`，
**不占用任何原版物品**，所以不会和别的插件抢物品、也不会被别人的数据包改掉。

## 怎么获得

```text
/ca tools
```

- **只能在创造模式领取**（物品没有合成表，生存拿不到）；
- 也可以在创造物品栏的"装备"分类里找到；
- `/ca tools list` 看每个工具的功能，`/ca tools status` 看物品包是否生效。

首次启动插件会**自动把物品包装到服务端**并写入世界包列表，然后提示：

```text
[CALL] 内置工具物品已安装（19 个文件，已写入世界包列表），重启服务器后生效
```

**重启一次服务器**后物品才存在，之后启动会打印 `[CALL] tool items ready`。

## 五个工具

| 工具 | 左键 | 右键 | 说明 |
|---|---|---|---|
| ⚙ 建造助手 · 菜单 | — | 打开主菜单 | 等同于 `/ca` |
| 选区魔杖 | 设 **A** 点 | 设 **B** 点 | 拿着它**不会破坏方块**，也不会放置方块 |
| 复制魔杖 | — | 复制当前选区 | 等同于 `/ca copy` |
| 粘贴魔杖 | — | 粘贴到点击的方块 | 等同于 `/ca paste` |
| 预览魔杖 | 换落点 | 设落点 / 再点一次旋转 90° | 潜行 + 右键 = 确认粘贴 · **潜行 + 左键 = 取消预览** |
| 调整魔杖 | 切换旋转基准 | 朝点击的那一面挪 1 格 | 潜行 + 右键 = 反方向 |

> 升级后新加的工具，绑定会自动补进你的设置（登录时、以及第一次点击时各补一次），
> 不需要重进服务器。如果点击仍然没反应，看聊天栏的提示，或用 `/ca tools debug` 查。

> 左键在 LSE 里**无法拦截**，所以插件用物品的 `can_destroy_in_creative: false` 加上
> `onDestroyBlock` 取消破坏做双保险 —— 拿工具挖方块不会真的挖掉。

## 预览怎么用

3.3.0 起预览会**真的把方块画出来**（客户端可见，不写世界）：

```text
1. 选区魔杖：左键 A 点、右键 B 点
2. 复制魔杖：右键复制
3. 预览魔杖：右键点方块 —— 目标位置出现【真方块 + 蓝色线框 + 尺寸/角度标签】
4. 再右键 = 旋转 90°（默认「原地」：框内排布转，框始终从落点这一格长出去，不会整体跳位）；左键 = 换个落点
5. 潜行 + 右键 = 确认，按预览的朝向真正粘贴
6. 位置差一格？用调整魔杖右键点方块的某个面，就朝那一面挪一格；潜行右键反向
7. 想放弃：**潜行 + 预览魔杖左键**点任意方块 = 立即取消（方块、鬼影、倒计时一起清掉）
```

也可以全用指令：

| 指令 | 作用 |
|---|---|
| `/ca preview set [x y z]` | 设落点（不给坐标就用脚下） |
| `/ca preview rotate` | 旋转 90° |
| `/ca preview mirror` | 切换镜像：none → x → z → xz |
| `/ca preview pivot [inplace\|anchor]` | 旋转基准：原地（默认）/ 绕落点（框转到相邻象限） |
| `/ca preview nudge <dx> <dy> <dz>` | 相对微调，预览和粘贴一起走；不带参数 = 清零 |
| `/ca preview confirm` | 确认粘贴 |
| `/ca preview cancel` | 取消预览（同时清掉已生成的方块） |
| `/ca preview mode ghost\|wireframe` | 切换"真方块"或"只线框"，写入配置 |
| `/ca preview info` | 看当前生成数量、上限、缩放 |
| `/ca preview probe` | 位置测量：脚下立 5 格标尺 + 1 个草方块，看它落在第几格 |
| `/ca preview probe <格数>` | 把测出来的格数保存成 `previewBlockYCorrection` 并重建预览 |
| `/ca preview calib` | 尺寸校准：摆不同 `scale` 的石头，挑刚好填满线框的那个 |
| `/ca tools debug` | 点工具没反应时用：打印手持物品、显示名、左右键命中哪条绑定、物品包状态 |

预览 **60 秒**没操作会自动取消（`previewTimeout` 可改），剩余时间会显示在 **Boss 条**上
（3.9.0 起）：标题是一行倒计时，血条随时间收缩，剩 10 秒转红、剩 5 秒提示即将取消。
每次旋转/挪动都会重置成 60 秒并立刻重新显示；**3.9.1 起默认从预览开始就显示到底**（原来只在最后 20 秒出现）。

Boss 条万一不刷新（`/ca preview bar` 能看出原因），倒计时会**自动改用动作栏**，此时选区文字会让位给倒计时，不会互相覆盖。诊断命令：

| 命令 | 作用 |
|---|---|
| `/ca preview bar` | 看库是否可用、本玩家条数、我们持有的 id、库内记录、`probe` 输出 |
| `/ca preview bar test` | 6 秒自检：建一条、每秒改标题与血条、打印每次返回值，最后删除 |
| `/ca preview bar clear` | 只删 CALL 自己建的那一条 |

| 想要 | 怎么调 |
|---|---|
| 全程都显示倒计时 | `previewCountdown: "always"` |
| 完全不显示 | `previewCountdown: "off"` |
| 提前取消（不等超时） | 潜行 + 预览魔杖左键点方块；或 `/ca preview cancel` |

### Boss 条为什么是「重建」而不是「刷新」

HologramLib 的 `bossBar*` 用 `bossBarAdd` 返回的 **64 位 id** 去更新/删除，而这个 id 经脚本层会丢精度（实测 `0x7000000000000000` → 传回去变成 `…929000`），`setTitle`/`setHealth`/`remove` 一律返回 false、`getInfo` 说 `not_found`——条建出来就再也改不了。

所以 CALL 的处理是：先用原样 id 试一次；不行就**每秒整条重建**（`bossBarRemoveAll` + `bossBarAdd`），倒计时照样走、结束时清干净。重建只影响该玩家自己的条；如果服务器上还有别的插件在用 Boss 条，把 `previewBossBarRebuild` 设为 `false`，倒计时会自动改用动作栏。

没有 HologramLib 时同样回退动作栏。

## 方块是怎么画出来的（3.6.0 起）

预览用的是 HologramLib 的 **`viewBlock(player, x, y, z, blockId)`**：只在**你这一台客户端**上把
这一格显示成某个方块。服务端世界、存档、别的玩家看到的都不变。

它和之前的 `itemDisplay*` 有本质区别：

| | 老的 `itemDisplay*` | 现在的 `viewBlock` |
|---|---|---|
| 实现 | 客户端造一只**假生物**（fox）主手拿着方块 | 只发一条方块更新包 |
| 会不会动 | 生物有呼吸/待机动画，方块**跟着飘** | 完全静止 |
| 开销 | 一个方块 = 一只实体，几千个直接掉帧 | 一个方块 = 一条包 |
| 观感 | 模型姿态拼出来的「像方块」 | 就是真方块：正确模型、朝向、光照 |

## 性能与上限

| 保护 | 说明 |
|---|---|
| **表面剔除** | 只画能看见的方块（六面都被挡住的内部方块直接丢弃）。实心 20×20×20 从 8000 个降到约 2400 个 |
| **数量上限** | `previewMaxBlocks`（默认 **8000**，上限 50000）。超过的部分不画，并提示「已按上限截断」 |
| **分批发送** | 每 tick 发 `previewBatchSize`（默认 **1000**）格，带进度提示，随时可取消 |
| **增量刷新** | 旋转/换落点只补发**差异**格子；转回 0° 时一条包都不发 |

只有预览者本人能看到；别人不受影响。

## 超大建筑：边走边加载（3.7.0 起）

建筑再大也不会「超过上限就整块不画」了，预览会按大小自动选一种模式：

| 模式 | 什么时候 | 画什么 |
|---|---|---|
| **全量** | 表面方块 ≤ `previewMaxBlocks`（默认 12000） | 全部方块，和以前一样 |
| **窗口** | 表面方块更多 | 只画你周围 `previewRadius`（默认 48 格）内的方块，按距离由近到远；**走动时窗口跟着走**，身后超出范围的自动清掉 |
| **懒解析** | 选区本身超大（> `previewMaxCells`，默认 80 万格） | 只解析窗口命中的 64 切片（LRU 缓存），**走到哪解析到哪**，不再报「区域太大」 |

配套开关：

- 朝**前方的预取**：窗口朝你视线那一侧多取 `previewPrefetch`（默认 16）格，前进时前方不会空白；
- **低精度外壳**：窗口模式下额外画一层按步长抽样的骨架（`previewOutline`/`previewOutlineStep`），站远处也能看出轮廓；懒解析模式下没有全局表面列表，只画线框；
- `/ca preview refresh`：手动立刻重算窗口（走位卡住时用）；
- `/ca preview radius <16-192>`：本次预览临时改半径；
- `/ca preview info`：显示当前模式、总表面/窗口、已覆盖格数。

## 为什么大建筑现在转得动（3.8.0）

这一版没有靠「少画一点」，而是把两处真正的开销去掉了（下面都是本机实测，同一份 30 万格选区）：

| 环节 | 之前 | 现在 |
|---|---|---|
| **表面剔除**（加载时一次） | 624 ms | **约 13~26 ms** |
| **旋转重建索引**（每次旋转） | 26 ms（4.8 万方块）/ 65 ms（12 万） | **≈0**（索引不再重建，只重跑窗口查询） |
| **发送** | 固定每轮 1000 格，1.2 万格 = 12 轮 | **按时间预算自适应**（`previewTickBudgetMs`，默认 8ms/轮） |
| **连点旋转** | 差量往队列里**追加**，越点越慢 | 队列**整体替换**，只发最终状态 |

具体做法：

- 剔除改成一张 `Uint8Array` 占位图，邻居判断变成整数下标加减 —— 之前每格要拼 7 个字符串；
- 空间索引改成**剪贴板坐标**（与旋转无关），构建一次，旋转/换落点只重新查询窗口；
- `viewBlock` 的原生函数引用被缓存下来直接调用，省掉每次的查找与参数打包；
- 每轮 pump 按耗时掐断，慢机器不会因为一次发太多而卡顿。

库这一侧（作者说得对）：HologramLib 到 1.35.0 都**只有逐格的 `viewBlock`**，没有批量接口（1.35 的 `shapeDrawBatch` 是形状，不是方块）。所以省下来的只能是「算」和「调度」。

## 结构文件放在哪（3.9.5-beta1 起）

所有结构按「玩家 / 名字 / 结构 id」分层，一个人一个目录，不会互相覆盖：

```text
data/nbt/
  Allen13in/                     ← 玩家目录（用玩家名，改名会自动搬）
    领地01号/                     ← 保存时填的名字；没填名字 = 结构 id
      mw4w5g20ay.mcstructure     ← 单切片就是 <id>.mcstructure
      mw4w5g20ay_1_0.mcstructure ← 超过 64 格切片才带 _x_z
    copy/<id>/…                  ← 剪贴板（退出/重启保留）
    undo/<id>/…  redo/<id>/…     ← 撤销/重做快照
  public/
    领地02号/                     ← 公共结构：文件夹名就是显示名
      <id>.mcstructure           ← 手动放进来即可，打开菜单自动刷新
  _legacy/                       ← 迁移前的原始扁平文件备份（可删）
  _orphan/                       ← 无法归属的旧文件（确认后可删）
```

规则：

- 名字里的 `\ / : * ? " < > |` 会被替换成 `_`，首尾空格与结尾的点会去掉，超长截断——不会出现建不出文件夹的情况；
- 公共结构**只读**：插件不会改 `public/` 里的文件，增删改名都在文件系统里做，打开菜单即热加载；
- 首次升级会自动迁移旧文件，原文件先在 `_legacy/` 备份一份。
## 清理是怎么保证的

- 只清**自己登记过的坐标**（`viewClearBlock`），**从不调用 `viewClearAll`** —— 那会连带清掉
  别的插件给同一名玩家做的覆盖；
- 清理按 tick 分批，取消/超时/确认粘贴时都会走同一条路径；
- 玩家中途离线时，覆盖会按玩家名留在库里，等他重新进服时再补清。

## 预览的局限

!> **看不见方块状态**。覆盖只带方块 id，不带 states：
>
> - 对的：方块种类、**每一格的位置**、大小、图案（旋转/镜像后的排布）
> - 不对的：台阶朝哪边、半砖上/下半、栅栏连接、火把方向 —— 都会显示成默认状态

预览的方块**不会跟着旋转**：粘贴只搬格子、不改方块 states，所以鬼影显示的就是最终写进去的朝向。
预览是"**这个位置放什么方块**"的准确示意（3.4.0 起与粘贴逐格一致），细节朝向以真正粘贴后的结果为准（不满意 `/ca undo`）。

## 还需要的库能力

- `viewBlock` / `viewClearBlock`（HologramLib 的 `view*` 域，1.30.0 / LL 26.51.4 起就有）：
  画方块、擦方块；
- `DebugShape` 域：画选区线框和预览框；
- `itemDisplay*` 只还被 `/ca preview probe`、`trim`、`calib` 用来做位置/尺寸校准。

## 没装 HologramLib 会怎样

- 选区线框自动退回**粒子框**（`areaDisplayMode: wireframe` 时）；
- 预览仍然可用，但**只有线框**，并且会提示"方块预览不可用"；
- 其余工具（菜单、选区、复制、粘贴）**完全不受影响**。

## 改键 / 改绑定

工具走的是和旧快捷物品完全相同的绑定系统：

```text
/ca tool bind   拿着物品执行，把自己的手持物品绑到指令
/ca tool list   查看当前绑定
/ca tool unbind 解绑
```

默认绑定写在 `configs.json` 的 `default.items` 里，按**物品 id** 匹配
（例如 `call:wand_select`），所以玩家自己改过的绑定不会被更新覆盖。
